Limitations:  
The system has several security and operational limitations. Generated code and unittests share an interpreter, which may allow child counts to be forged and does not provide semantic correctness attestation. AppContainer shares the host kernel, meaning that OS resources already accessible to AppContainers remain accessible. Profile private storage is writable without disk quota enforcement, and staging time is outside the execution deadline. Only the CPython standard library is staged, with no third-party tool dependencies. Unsupported hosts or setup/cleanup failures deny execution, with no ordinary host fallback available. Additionally, native AppContainer has no network capabilities, and explicit inherited handles and minimal environment are enforced. Job memory is limited to 512 MiB, with eight processes, a wall timeout of 30 seconds, and a bounded combined output of 256 KiB. Read-only disposable staging is used, with unique profiles and copied runtime per invocation, and cleanup is performed. Ledger owner, operation, and length-framed source/test SHA256 are used, along with independent non-executing syntax checks. No empty, skipped, expected-failure, failed, changed, stale, or missing observations are accepted. Manager final-stage and execution gates are in place, with an explicit existing-tool reverification action.
