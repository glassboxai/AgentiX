# OWASP GenAI LLM Top 10 2026 control matrix

Date: 2026-10-24. Scope: the Windows desktop, single-Windows-user deployment of AgentiX v3. This is an engineering control assessment, not OWASP certification or a claim that prompt injection is solved. The authoritative published list is https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/blob/main/2026/README.md (published 2026-08-04). The 2025 numbering must not be substituted.

## Trust boundaries

Browser input, user tasks, model output and generated source/tests are untrusted. Host-owned approvals, byte receipts and independent expected values are authorization evidence. Generated Python runs only in native Windows AppContainer/Job Object isolation; there is no host-execution fallback. Provider credentials remain in the Windows user credential boundary and the owning SDK client's memory, outside tool parameters, generated child inputs and agent prompts. External provider activation explicitly discloses task/artifact content to that provider after session consent.

The UI listens only on loopback. Gradio session routing and opaque tokens isolate workflows but are not authenticated multi-user identities. Anyone controlling this Windows user or its browser/processes can access its data and credentials; this release is not a remotely exposed multi-tenant service. Saved profiles are shared within that Windows user, while selection, consent, clients, approvals and execution evidence belong to individual application sessions.

## Provider transport policy

Ollama is restricted to HTTP loopback. External providers require HTTPS port 443, no URL credentials/query/fragment, public DNS resolution and explicit session consent. OpenAI uses its fixed official endpoint; compatible APIs use an explicitly configured public base path. Installed CrewAI request interceptors revalidate destination origin/base path and public DNS, and reject redirects in synchronous and asynchronous transport. Explicit transports avoid inherited environment proxies. DNS validation and connection remain separate operations: DNS rebinding protection is incomplete without a network-enforcing egress proxy. Private enterprise endpoints are intentionally not supported in this profile.

Provider model names are configuration, not executable paths. The accepted name syntax is bounded and supports ordinary namespace/model names, while rejecting traversal and empty namespace components. Remote inference and billing are not exercised by this block's synthetic-client tests.

## Persistent credential lifecycle

Profiles contain display name, provider, model, endpoint, revision, opaque ID and owned credential references. Consent is never saved. New sessions start local. Saved profiles live under the current host-resolved LOCALAPPDATA/AgentiX/v3/data/model-profiles directory, including packaged-host Windows path virtualization. Inherited Windows user-directory permissions apply; this is not a separate protection boundary against the same user.

New key versions use new credential targets. Metadata writes are serialized across processes and replaced atomically. A failed precommit write leaves the prior profile valid. Postcommit credential cleanup retains old references for retry. Crash between a vault write and the metadata commit can leave an orphan credential: no cross-service transactional rollback is claimed. Explicit deletion removes only validated references owned by the selected profile, and leaves metadata on incomplete deletion so it can be retried. Removing a saved profile does not revoke a supplier API key or erase already loaded keys in other active sessions.

Windows Credential Manager uses local-machine persistence for the current Windows user, not roaming. Keys necessarily exist briefly in browser input, request memory, native buffers and the owning SDK client. Python cannot promise secure memory zeroization. Host redaction is bounded defense in depth rather than universal data-loss prevention.

## PROFILE-001 update

Local Ollama profiles persist only validated metadata and an empty credential reference. They do not depend on Windows Credential Manager. External credential ownership/consent rules are retained, including safe retirement on provider conversion. Public profile diagnostics use only a closed code/message catalog plus optional numeric native status; no untrusted exception text is displayed. Refresh retains a failed-save reason. New integration evidence combines real Gradio, temporary metadata and a disposable native credential, supplementing doubled-browser and independent-vault tests. This does not establish the cause of a nonreproduced historical user failure.

## REUSE-001 agency boundary

Repeated queries may reuse a successful, reviewed, unchanged tool within its owning session. This deliberately replaces mandatory repeated acceptance for that case; it does not weaken AppContainer permissions, public function coverage or fresh execution evidence. Exact-byte drift, owner changes and revocation invalidate grants. Unknown capabilities require manual approval of the exact call. The conservative AST vocabulary is a UX eligibility gate, not proof of purity, universal correctness or immunity to prompt injection. A model cannot create grants by prose or disk metadata. Same-user host tampering and malicious isolated result fabrication remain residual risks.

## REUSE-002 persistent agency scope

The user now authorizes durable reuse of successful reviewed functions on this local deployment, across sessions and restarts. Records are sealed with user-scoped DPAPI and machine-bound entropy outside artifact storage, bound to exact hashes/root/functions and maintained security policy. No model message, unprotected artifact marker or unittest report creates trust. Invalid protection, changed artifacts/policy or a relocated storage root requires review. Sensitive/unclassified calls still require exact-call confirmation and AppContainer permissions are unchanged.

These controls assume the local host user and deployment are trusted; browser routing identities are not Windows account authentication. Same-user malware, rollback of a valid old record together with matching artifacts, unavailable storage and already-dispatched concurrent calls remain residual limits. No cross-service transaction, perfect rollback protection or instantaneous cross-process revocation is claimed. Finite acceptance still does not establish universal correctness.

Native API reference: [CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata) and [CryptUnprotectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptunprotectdata). User protection is used without LOCAL_MACHINE; explicit MachineGuid entropy limits roaming-profile portability.
